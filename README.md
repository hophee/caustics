# Клинический компас

Хакатонный прототип команды «Каустики» для сопровождения пациентов и поддержки работы врача.

Приложение объединяет карточку пациента, подбор и проверку терапии, опросники, дневник самочувствия, контроль приёма препаратов и уведомления о событиях, требующих внимания врача.

## Возможности

**Для врача:**

- просмотр пациентов, их состояния и динамики;
- ведение карточки пациента и приёмов;
- назначение опросников и просмотр результатов;
- подбор терапии с учётом диагноза и проверками безопасности;
- просмотр дневника и соблюдения назначений;
- обработка предупреждений и сообщений о нежелательных реакциях;
- работа с направлениями и документами.

**Для пациента:**

- просмотр назначений;
- отметки о приёме или пропуске препаратов;
- заполнение опросников и дневника самочувствия;
- сообщение о нежелательной реакции;
- просмотр приёмов, направлений и документов.

Это демонстрационный прототип. Для проверки используйте вымышленные данные. Результаты автоматических проверок требуют оценки врача.

## Быстрый запуск

Основной способ запуска — Docker Compose. Он поднимает PostgreSQL, применяет миграции, запускает API, веб-интерфейс и фоновый обработчик.

### Требования

- Docker с поддержкой `docker compose`;
- доступ к интернету при первой сборке;
- файл базы препаратов `ohlp_fields_v4.csv`.

Команды выполняются из корня репозитория.

### 1. Подготовить настройки

Скопируйте `.env.example` в `.env`.

**Linux / macOS:**

```bash
cp .env.example .env
```

**PowerShell:**

```powershell
Copy-Item .env.example .env
```

В `.env` заполните следующие параметры:

```dotenv
POSTGRES_PASSWORD=<случайный пароль базы данных>
KOMPAS_JWT_SECRET=<случайная строка длиной не менее 32 символов>
KOMPAS_INVITE_SECRET=<другая случайная строка длиной не менее 32 символов>

KOMPAS_WEB_BIND=127.0.0.1
KOMPAS_WEB_PORT=8080

KOMPAS_DEMO_MODE=true
KOMPAS_TEXT_MODEL=keywords
HF_CACHE_HOST_PATH=./.hf-cache
```

Значения в угловых скобках нужно заменить. Для генерации секретов можно использовать:

```bash
openssl rand -hex 32
```

Запускайте команду отдельно для каждого секрета. Файл `.env` не следует добавлять в Git.

Создайте пустую папку `.hf-cache`:

```bash
mkdir .hf-cache
```

Она используется как точка подключения кеша в текущей конфигурации Compose. В режиме `keywords` веса языковых моделей не нужны.

### 2. Подготовить базу препаратов

По умолчанию ожидается файл:

```text
ohlp_fields_v4.csv
```

в корне репозитория.

Если файл находится в другом месте, укажите путь в `.env`:

```dotenv
KOMPAS_OHLP_HOST_PATH=/absolute/path/to/ohlp_fields_v4.csv
```

В Windows можно использовать путь с прямыми слешами:

```dotenv
KOMPAS_OHLP_HOST_PATH=D:/data/ohlp_fields_v4.csv
```

Путь должен указывать на существующий файл. Если база не включена в публичную поставку, её необходимо получить отдельно до запуска. Она нужна для поиска препаратов и проверок терапии.

### 3. Запустить приложение

```bash
docker compose up -d --build
docker compose ps
```

Первая сборка может занять заметное время: образ содержит зависимости обработки текста, даже если для демонстрации выбран режим `keywords`.

После запуска:

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:8080 | Веб-интерфейс |
| http://127.0.0.1:8080/docs | Интерактивная документация API |
| http://127.0.0.1:8080/openapi.json | Спецификация OpenAPI |

Сервис `migrate` выполняет миграции и завершается. Его завершение с кодом `0` — штатное поведение.

## Сценарий проверки

При `KOMPAS_DEMO_MODE=true` на странице входа доступны кнопки «Попробовать как врач» и «Попробовать как пациент». Приложение создаёт демонстрационные учётные записи и синтетические данные.

### Кабинет врача

1. Войдите через «Попробовать как врач».
2. Откройте список пациентов и карточку одного из них.
3. Посмотрите сведения о пациенте, дневник и результаты опросников.
4. Откройте раздел терапии, найдите препарат и проверьте предлагаемые предупреждения.
5. Посмотрите доступные действия с приёмами, назначениями и уведомлениями.

### Кабинет пациента

1. Выйдите из кабинета врача или откройте отдельный профиль браузера.
2. Войдите через «Попробовать как пациент».
3. Посмотрите назначения и отметьте приём препарата.
4. Добавьте запись в дневник.
5. Заполните доступный опросник.
6. Проверьте форму сообщения о нежелательной реакции.

Демонстрационные входы не следует считать гарантированно одной и той же парой «врач — пациент». Для проверки полного связанного сценария создайте врача, затем пациента через его кабинет и активируйте учётную запись пациента по приглашению.

### Создание врача вручную

```bash
docker compose exec api kompas create-doctor doctor@example.ru "Иванова Ирина Петровна"
```

Следуйте запросам CLI для задания пароля. После этого войдите в веб-интерфейс с созданной учётной записью.

## Обработка текста дневника

Предусмотрены два режима:

| Режим | Поведение |
|---|---|
| `KOMPAS_TEXT_MODEL=keywords` | Проверка по ключевым словам без запуска языковой модели |
| `KOMPAS_TEXT_MODEL=llm` | Локальная обработка текста языковыми моделями |

Для первого знакомства рекомендуется `keywords`.

В конфигурации LLM используются Qwen3-4B и локальный переводчик opus-mt-ru-en. Для этого режима требуются заранее загруженные совместимые веса в кеше Hugging Face, около 8 ГБ дискового пространства для весов и ориентировочно 16 ГБ оперативной памяти.

Текущий Compose запускает модели в офлайн-режиме: отсутствующие веса автоматически не скачиваются. Путь к подготовленному кешу задаётся через `HF_CACHE_HOST_PATH`.

Режим `keywords` позволяет проверить интерфейс и основные процессы, но не воспроизводит поведение языковой модели.

## Устройство проекта

```text
src/
  backend/
    src/kompas/       API, бизнес-логика, CLI и фоновый обработчик
    knowledge_data/  Шкалы, правила и справочные данные
    migrations/      Миграции PostgreSQL
    tests/           Тесты backend и API
    examples/        Примеры входных данных

  frontend/
    src/             Веб-интерфейс
    e2e/             Браузерные тесты

deploy/              Dockerfile и файлы поставки
tools/               Утилиты разработки и импорта
compose.yaml         Конфигурация локального запуска
.env.example         Шаблон переменных окружения
```

Основные технологии:

- **Frontend:** React, TypeScript, Vite.
- **Backend:** Python 3.13+, FastAPI, SQLAlchemy, Alembic.
- **База данных:** PostgreSQL.
- **Обработка текста:** PyTorch и Transformers.
- **Проверки:** pytest, Vitest, Playwright.

В Docker веб-интерфейс собирается вместе с backend и обслуживается тем же приложением. API доступен по префиксу `/api/v1`.

## Запуск тестов

Для запуска вне Docker нужны Python 3.13+, `uv`, Node.js 22 и npm.

### Frontend

```bash
cd src/frontend
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

### Backend: проверки без PostgreSQL

```bash
cd src/backend
uv sync --frozen
uv run pytest --ignore=tests/api
```

Отдельные проверки моделей могут требовать дополнительных ресурсов или пропускаться при их отсутствии.

### Backend: полный набор

```bash
uv run pytest
```

API-тесты требуют отдельной тестовой PostgreSQL. Адрес можно передать через `KOMPAS_TEST_DATABASE_URL`. Если переменная не задана, тесты пытаются запустить локальную базу через `tools/devdb`.

**Используйте только отдельную тестовую БД:** тестовые фикстуры очищают таблицы. При недоступности БД API-тесты могут быть пропущены — проверяйте итоговый отчёт pytest.

## Диагностика

Состояние сервисов:

```bash
docker compose ps
```

Последние сообщения приложения:

```bash
docker compose logs --tail=100 api worker migrate
```

Типовые ситуации:

| Проблема | Что проверить |
|---|---|
| Compose сообщает о незаданной переменной | Заполнены ли секреты в `.env` |
| Ошибка длины секрета | `KOMPAS_JWT_SECRET` и `KOMPAS_INVITE_SECRET` должны содержать не менее 32 символов |
| Не открывается сайт | Завершилась ли сборка, запущен ли `api`, свободен ли порт 8080 |
| Не работает поиск препаратов | Существует ли CSV и правильно ли задан `KOMPAS_OHLP_HOST_PATH` |
| Нет демонстрационных кнопок | Задано ли `KOMPAS_DEMO_MODE=true` |
| Не обрабатываются фоновые события | Запущен ли `worker`, нет ли ошибок в его журнале |
| Ошибка загрузки модели | Подготовлен ли кеш весов; для проверки без модели используйте `keywords` |

После изменения `.env` примените настройки:

```bash
docker compose up -d
```

## Остановка и сброс

Остановить приложение с сохранением базы:

```bash
docker compose down
```

Полностью удалить базу демонстрационного стенда:

```bash
docker compose down -v
```

Вторая команда удаляет Docker-том с PostgreSQL. При следующем запуске база будет создана заново.
